# v1.1 审计修复记录

本记录说明 Markdown Design Baseline 从 v1.0 Draft 升级到 v1.1 Accepted 所修复的问题；它不替代任何叶子事实源。

## 已修复的 P0 问题

1. **事实源与内容不匹配**：补全 Product Modes、正式状态机、安全、测试、API、Compiler、Execution 和子系统叶子文档；Overall Design 改为集成摘要并链接事实源。
2. **两套 Phase**：统一为 `Preparation + Phase 0–9`，同步 Roadmap、Acceptance、Overall 和 DDL 语义。
3. **状态漂移**：状态值统一为 lowercase kebab-case；建立逐实体转换表，删除重复的旧 snake_case 图。
4. **OpenAPI 不完整**：扩展到 100 paths / 103 operations，补齐 Discovery、Review、Planning、Execution、Dataset、Secret、Cutover、Archive、SSE 和错误响应；使用正式 enum 与 typed page。
5. **DDL 领域冲突**：支持多 Blueprint 输入；补 Plan Stage/Gate/Risk；复合 FK 限制同 Plan Action edge；分离 root/rollback active Run；保留 queue row；WorkerLease 为权威；共享读锁模型；业务表 workspace scope；失败 Snapshot 归属 CollectionRun。

## 已修复的 P1 问题

- 四种 Plan Compiler 增加输入、阶段、字段映射、Gate、错误、Rollback 和 Golden Fixture 要求。
- 正式引入 `ExecutionCommitRecord`、`ControlPlaneOperation` 和统一命名。
- Security 增加 Threat ID、控制、供应链、审批和验证要求。
- Operations 增加备份恢复、Worker、Repair、升级和 Incident Runbook。
- Testing/Acceptance 增加固定 Fixture、故障注入、Evidence Bundle 和 PASS/PARTIAL/FAIL。
- ADR 增加驱动因素、替代方案、实施迁移、风险和可逆性。

## 自动验证

根目录 `tools/validate_design_docs.py` 检查：

- Front matter、版本、唯一 ID；
- Markdown 相对链接和锚点；
- code fence；
- legacy type/state/Phase；
- Mermaid metadata/基础结构；
- YAML、OpenAPI `$ref`、operationId、path parameter、错误响应；
- DDL 必要对象和关键冲突模式。
